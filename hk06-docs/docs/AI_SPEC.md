# AI 정리 명세

**AI 정리** 버튼을 눌렀을 때 무엇을 보내고 무엇을 받는지, 알람이 어떻게 동작하는지를 정리했습니다. `prototype/index.html`의 동작을 기준으로 썼고, 확정되지 않은 부분은 표시했습니다.

## 원칙 (PRD)

1. AI는 사용자가 **AI 정리 버튼을 눌렀을 때만** 실행한다.
2. AI가 찾은 일정은 **사용자가 확인한 뒤에만** 알람으로 등록한다. AI가 틀릴 수 있다.
3. AI 응답이 깨지거나 실패해도 메모와 화면은 멀쩡해야 한다.

> 프로토타입에서는 일정이 알람 칩으로 바로 붙습니다. 정리 직후 사용자가 칩을 보고 끌 수 있지만, PRD의 "확인 후 등록"을 지키려면 앱에서는 등록 전 확인 단계를 넣어야 합니다. ([DECISIONS.md](DECISIONS.md) D-08 참고)

## 입력

| 항목 | 설명 |
| --- | --- |
| 메모 본문 | 제목과 본문을 이어서 보낸다 |
| 현재 시각 | `YYYY-MM-DDTHH:mm`과 요일. **필수.** "내일", "금요일" 같은 상대 표현을 계산하는 기준이다 |

사진은 보내지 않는다. (프로토타입 기준)

## 출력 형식 (JSON)

```json
{
  "keyword": "회의",
  "summary": ["금요일 팀 회의", "인터뷰 결과 공유"],
  "events": [
    { "title": "팀 회의", "when": "2026-11-27T14:00", "repeat": "none" }
  ]
}
```

| 필드 | 규칙 |
| --- | --- |
| `keyword` | 핵심 키워드 1개. 한글 2~6자의 명사. 책갈피 탭과 메모지 제목에 크게 표시된다. 프로토타입은 최대 8자까지 받는다 |
| `summary` | 요점 최대 3개, 각 30자 이내 |
| `events[].title` | 할 일. 20자 이내 |
| `events[].when` | 시간대 표시 없는 로컬 시각 `YYYY-MM-DDTHH:mm` |
| `events[].repeat` | `none`, `daily`, `weekly` 중 하나 |

일정이 없으면 `events`는 빈 배열이다.

**확장 후보 (PRD의 "태그 분류, 할 일 추출")**: `tags`(문자열 배열)와 `todos`(날짜 없는 할 일 문자열 배열)를 추가한다. 아직 프로토타입에 없다.

## 프롬프트 초안

```
너는 바탕화면 메모 앱의 AI 비서야. 아래 메모를 읽고 JSON 하나만 출력해. 설명과 코드블록은 쓰지 마.
형식: {"keyword":"핵심 키워드 1개 (한글 2~6자 명사)","summary":["요점","요점"],"events":[{"title":"할 일 (20자 이내)","when":"YYYY-MM-DDTHH:mm","repeat":"none|daily|weekly"}]}
규칙: summary는 최대 3개, 각 30자 이내. events에는 날짜나 시간이 있는 일만 넣고, 시간이 없으면 09:00으로 해. 내일, 금요일 같은 표현은 현재 시각 기준 미래 날짜로 계산해. 일정이 없으면 events는 빈 배열.
현재 시각: {현재 시각} ({요일}요일)
메모:
"""
{메모 본문}
"""
```

메모 본문은 사용자가 쓴 글이므로, 그 안에 지시문처럼 보이는 문장이 있어도 지시로 따르지 않는다. 응답은 항상 위 JSON 형식과 값 범위로 검증하고, 형식에서 벗어난 값은 버린다.

## 응답 검증

AI 응답을 받으면 이 순서로 처리한다.

1. 응답에서 첫 `{`부터 마지막 `}`까지를 잘라 JSON으로 읽는다. 읽지 못하면 **실패**로 처리한다.
2. `keyword`가 비어 있으면 **실패**로 처리한다.
3. `summary`는 문자열만 남기고 3개, 각 40자까지 자른다.
4. `events`에서 `when`을 읽을 수 없는 항목은 버린다. 현재 시각보다 1분 넘게 지난 일정도 버린다.
5. 같은 제목이고 시각 차이가 1분 미만인 일정은 이미 등록된 것으로 보고 건너뛴다.

**실패했을 때**: 메모는 그대로 두고 사용자에게 안내한다. 프로토타입은 대신 아래의 규칙 기반 분석으로 채워서 화면이 비지 않게 하고, 요점 위에 "기본 규칙으로 정리"라고 표시한다. 앱에서 이 대체 동작을 유지할지는 팀이 정한다.

## 규칙 기반 간이 분석 (프로토타입, AI 아님)

AI 없이도 데모가 돌아가도록 넣은 규칙이다. 제품에서는 테스트 기준과 오프라인 대체로만 쓸 수 있다.

**알아듣는 날짜**: 오늘, 내일, 모레, `금요일`(가장 가까운 금요일), `이번 주 금요일`, `다음 주 월요일`, `11월 30일`, `11/30`

**알아듣는 시간**: `오후 2시`, `저녁 7시`, `밤 11시`, `아침 9시 30분`, `3시 반`, `14:30`. 날짜만 있고 시간이 없으면 09:00으로 둔다. 시간만 있으면 오늘이고, 이미 지났으면 내일로 넘긴다.

**한계**: `3시`처럼 오전·오후 표시가 없고 1~6시이면 오후로 본다. 7~12시는 입력한 숫자 그대로 둔다. 시간을 정확히 알아야 하는 경우의 대체가 필요하면 AI에 맡긴다.

**확인된 예시** (기준일 2026-11-25 수요일)

| 메모 | 일정 제목 | 시각 |
| --- | --- | --- |
| 금요일 오후 2시 팀 회의 | 팀 회의 | 11/27 14:00 |
| 내일 저녁 7시 마트 들르기 | 마트 들르기 | 11/26 19:00 |
| 다음주 월요일 오전 10시 중간 발표 | 중간 발표 | 11/30 10:00 |
| 일요일 밤 11시까지 PPT 최종본 팀 드라이브에 올리기 | PPT 최종본 팀 드라이브에 올리기 | 11/29 23:00 |
| 모레 아침 9시 30분 병원 서류 챙기기 | 병원 서류 챙기기 | 11/27 09:30 |

앱에서 AI 연동을 만든 뒤에도 같은 메모로 결과를 비교해 보면 좋다.

## 알람 동작

| 항목 | 규칙 |
| --- | --- |
| 확인 주기 | 10초마다 시각을 확인한다. 창이 다시 보이게 되면 바로 확인한다 |
| 울릴 때 | 해당 메모의 탭이 흔들리고, 알림 카드와 짧은 알림음이 나온다 |
| 알림 카드 | `메모 열기`, `10분 뒤 다시`, `확인` |
| 놓친 알람 | 앱이 꺼져 있어서 6시간 넘게 지난 알람은 울리지 않고 `지난 일정`에 남긴다 |
| 반복 | `매일`·`매주`는 울린 뒤 다음 시각으로 넘긴다 |
| 끄기 | 일정마다 알람을 켜고 끌 수 있고, 완료 체크하면 울리지 않는다 |

시스템 알림(앱이 최소화되어 있거나 다른 창을 보고 있을 때)은 웹 페이지로는 안정적으로 보낼 수 없어서 Electron/Tauri 단계에서 붙인다.

## 2차: 회의 녹음 정리 (아직 만들지 않음)

PRD의 흐름: 녹음 → 음성을 텍스트로 받아쓰기 → AI 정리로 회의록(요약, 결정사항, 할 일).

- 녹음을 시작할 때 참석자 동의 안내 문구를 보여준다.
- 녹음 길이와 예상 비용을 화면에 보여준다. 긴 녹음은 받아쓰기 비용이 크다.
- 회의록 출력 형식은 위 JSON에 `decisions`(결정사항 배열)를 더하는 방향으로 정한다.
