# 기여 방법

팀 프로젝트라서 충돌을 줄이는 최소한의 규칙만 적었습니다. 팀이 합의해서 바꿔도 됩니다.

## 브랜치

`main`은 항상 열어볼 수 있는 상태로 두고, 작업은 브랜치에서 합니다.

| 종류 | 이름 예시 |
| --- | --- |
| 새 기능 | `feat/ai-organize-button` |
| 버그 수정 | `fix/alarm-not-firing` |
| 문서 | `docs/update-prd` |
| 정리·설정 | `chore/add-gitignore` |

## 커밋 메시지

`종류: 한 줄 요약` 형식으로 쓰고, 한국어로 써도 됩니다.

```
feat: 책갈피 탭에 다음 알람 시각 표시
fix: 모레 아침 9시 30분이 9시로 인식되는 문제 수정
docs: PRD에 스티커 기능 추가
```

## PR

1. 작은 단위로 올립니다. 한 PR에는 한 가지 일만 담습니다.
2. 설명에 **무엇을 왜 바꿨는지**, **어떻게 확인했는지**를 적습니다. 화면이 바뀌면 스크린샷을 붙입니다.
3. 팀원 1명 이상이 확인한 뒤 합칩니다.
4. 기능이 바뀌면 관련 문서(`docs/`)도 같은 PR에서 고칩니다.

## 하면 안 되는 것

- API 키, 토큰, `.env` 파일을 커밋하지 않습니다. 실수로 올렸다면 키를 바로 폐기하고 새로 발급받으세요. 파일을 지우는 것만으로는 기록에서 사라지지 않습니다.
- `main`에 직접 푸시하지 않습니다.
- 팀원이 작업 중인 파일을 말없이 통째로 바꾸지 않습니다.

## 문서를 고칠 때

- 아직 정해지지 않은 내용은 [docs/DECISIONS.md](docs/DECISIONS.md)에 적고, 정해지면 PRD에 반영합니다.
- PRD는 팀이 함께 쓰는 기준 문서라서, 큰 변경은 PR 설명에 이유를 남깁니다.
